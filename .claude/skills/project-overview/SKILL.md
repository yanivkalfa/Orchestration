# Project overview — read first

## Read, in this order

1. `project/PROJECT.md` — name, description, platform, commands, modules, constraints, "done".
2. `docs/direction.md` — mission, what it is not, the yardstick.
3. `docs/project-overview.md` if it exists (the filled copy of `docs/project-overview-template.md`).
4. `docs/orchestration.md` — the one page of rules, and its "Standing rulings".
5. `plans/` — the row table of every wave file (status cells only; plan sections on demand).
6. `memory/MEMORY.md` — the index; open a memory file only when its line is relevant.

## Then state, in three lines

- What the project is (one sentence).
- What is in flight (rows `LAUNCHED`) and what is next (first `OPEN` row on a free module).
- Anything blocked, and by what.

## If PROJECT.md still has placeholders

Do not plan or build. List the unfilled `<placeholders>` in one message and ask the owner to fill
them (or offer a filled draft for the owner to confirm, one line per choice).

## If no wave file exists

The next step is the `research-pass` skill.

## Facts never quoted from memory

Row counts, wave totals, ruling numbers: read the file and count. A miscount in a status report is
a record defect.
